# DESIGN

## Purpose

Small end-to-end satellite-style TM/TC project. The C++ folder is a
host-side codec that lives alongside the existing C firmware
(`Core/Src/ccsds.c`) and Python ground station (`ground/ccsds_codec.py`),
provably byte-identical with both, plus a small NATS bridge that mirrors
the shape of real ground-segment messaging.

## Wire format

CCSDS 133.0-B-2 Space Packet, primary header + payload + CRC:

```
[ packet_id (2) | seq_ctl (2) | data_len (2) | payload | crc16 (2) ]

packet_id = vvv t s aaaaaaaaaaa
            ^   ^ ^ ^ APID (11 bits)
            |   | sec-hdr flag (1 bit, always 0 here)
            |   type: 0=TM, 1=TC
            version (3 bits, always 0)

seq_ctl  = ff cccccccccccccc   (2-bit flags, 14-bit sequence count)
data_len = (payload + crc) - 1, big-endian
```

`kMaxFrameLen` is 256 bytes, matching the firmware buffer cap.

## CRC variant

CRC-16/CCITT-FALSE (a.k.a. CRC-16/IBM-3740):

| param   | value  |
|---------|--------|
| poly    | 0x1021 |
| init    | 0xFFFF |
| refin   | false  |
| refout  | false  |
| xorout  | 0x0000 |
| check   | 0x29B1 for `"123456789"` |

This is *not* XMODEM (which uses init=0x0000 and check=0x31C3). The
ambiguous "CCITT/XMODEM" label in earlier docs was corrected once the
check value was independently computed.

## Implementations

| component       | path                                | role                                |
|-----------------|-------------------------------------|-------------------------------------|
| C firmware      | `Core/Src/ccsds.c`                  | runs on STM32F411RE under FreeRTOS  |
| Python codec    | `ground/ccsds_codec.py`             | host ground station                 |
| C++ codec       | `cpp/include/ccsds/codec.hpp`       | this folder                         |
| C++ framer      | `cpp/include/ccsds/framer.hpp`      | UART-like stream reassembly         |
| NATS bridge     | `cpp/include/ccsds/nats_bridge.hpp` | optional, opt-in via CMake          |

## Error handling

* `decode()` returns `std::optional<Packet>` and is `noexcept`. Any
  failure (short buffer, version mismatch, length-field inconsistency,
  CRC mismatch) returns `std::nullopt`. The streaming framer uses this
  as a cheap probe on every candidate alignment.
* `encode()` throws `std::invalid_argument` only for out-of-range API
  inputs (APID > 0x7FF, seq_count > 0x3FFF, frame > `kMaxFrameLen`).
  Everything else is constructed deterministically.
* The streaming `Framer` mirrors the firmware's RX strategy: length-
  driven framing, 1-byte slip on every decode failure or implausible
  length field. False-positive resync rate for CRC-16/CCITT is roughly
  1/65536 per slip. `slipped()` and `buffered()` are exposed as
  link-health counters.
* The NATS bridge silently drops frames that fail to decode (the CRC
  already told us they're noise), but its `dropped_count()` ticks up so
  the link's behavior is observable.

## Testing

* **Fixtures** (`tests/fixtures.hpp`): four real packets — HK, EVENT,
  PING, SET_TM_RATE — frozen as constexpr byte arrays from the proven
  Python codec.
* **Conformance** (`tests/conformance_test.cpp`): encode produces those
  exact bytes; decode produces the expected fields; decode-then-encode
  round-trips byte-for-byte; corrupted/truncated/wrong-version frames
  rejected; out-of-range encode inputs throw.
* **Framer** (`tests/framer_test.cpp`): single frame, split-across-
  pushes, garbage prefix, corrupted-then-valid, back-to-back valids,
  truncated-held-until-complete.
* **Differential** (`tests/differential_test.cpp`): 200 random valid
  packets generated by `ground/generate_fixtures.py` driving the Python
  codec; C++ must decode each and re-encode to the exact same bytes.
  This sweeps the parameter space the hand-picked fixtures don't.
* **Sanitizers**: separate CI job builds clang + `-fsanitize=address,
  undefined` and runs the full test set, including the NATS bridge,
  against a local nats-server.
* **Fuzzing** (`fuzz/fuzz_decode.cpp`): libFuzzer entry point covers
  `decode()`, encode-redecode symmetry, and the framer's resync logic.
  CI runs 60s as a smoke test; deep runs are run-locally / out-of-tree.

## Messaging

`cpp/include/ccsds/nats_bridge.hpp` provides a small NATS bridge:

```
tc.raw   ─► bridge ─► decode ─► JSON ─► tc.parsed
tm.raw   ─► bridge ─► decode ─► JSON ─► tm.parsed
```

Each parsed message is `{type, apid, seq_flags, seq_count, payload_hex}`.
Just enough for downstream consumers (dashboards, archivers, alerting)
to filter and route without parsing CCSDS themselves.

The bridge is opt-in via `-DCCSDS_WITH_NATS=ON` so the core build stays
dependency-free. cnats is pulled via FetchContent with TLS, streaming,
and examples disabled to keep the surface narrow. CI installs
`nats-server` v2.10.20 and runs a publish/subscribe round-trip test.

The streaming framer is intentionally NOT used here — NATS messages
arrive as bounded discrete payloads, which is the single-packet decode
path. A real ground segment using NATS would put framing at the
gateway, not on the bus.

## Scope

**In:** the codec, the streaming framer, conformance + differential +
fuzz testing, the NATS bridge.

**Out:** a full flight stack, real spacecraft bus integration, a
production ground system. The NATS bridge demonstrates the shape of
distributed-messaging integration, not a complete ground-segment
deployment.
